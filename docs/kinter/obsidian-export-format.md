# Work Journal 的 Obsidian 导出格式

## 默认行为和操作顺序

`work_journal_obsidian.export_mode` 默认值为 `preview_only`。在此模式下，系统可以生成 Markdown 预览，但不会写入 vault。实际写入需要：

1. 设置有效的 vault 路径和相对日报目录（默认目录名为 `Work Journal`）。
2. 将导出模式改为 `daily_log`。
3. 在日志页先生成预览，后端返回 Markdown、SHA-256、10 分钟有效的一次性确认 Token 和过期时间。
4. 用户在界面的确认对话框中确认导出；正式写入必须提交日期、hash 和 Token。

界面只允许在已有预览且日报导出已开启时发起确认；后端取出 Token 后立即使其失效，重新生成内容并核对日期、hash、vault、日报目录和冲突策略。缺失、过期、复用、内容变化或配置变化都会拒绝写入，并要求重新预览。Token 只保存在当前进程内，最多保留 10 条，应用重启后全部失效。预览命令本身不写文件。

## 输出内容

目标文件名为 `<YYYY-MM-DD>.md`，默认位于 `<vault>/Work Journal/`。生成内容使用中文 Markdown，包含：

- 标题：`# YYYY-MM-DD 工作日志`
- 今日时间分布（总时长、关联项目数、工作块数量）
- 主要推进项目
- 具体完成事项
- 沟通与会议
- 卡点和待补记
- 明日建议
- 证据摘要
- 隐私过滤说明

项目页已配置时，项目名写成 `[[Obsidian 页面|项目名]]`；低置信工作块带“（待确认）”。`excluded` 的 session 不写入预览或导出；`private` 的 session 以“私密工作”展示且不带证据。预览和导出都基于本地隐私过滤后的活动摘要。

## Vault 边界保护

日报目录必须是 vault 内的相对路径。绝对路径、盘符前缀、根目录和 `..` 都会被拒绝。程序在创建目录后会规范化 vault 与目标目录，并再次检查目标是否仍位于 vault 内；目标日报、备份文件和 `create_new` 候选文件名只要是符号链接、损坏链接、目录或规范化后越出 vault，都会拒绝。新文件使用独占创建，避免覆盖并降低检查后被替换为链接的竞态风险。日期必须是有效的 `YYYY-MM-DD`。

## 稳定标记、备份与冲突策略

写入的 Work Journal 区块有稳定标记，日期相同：

```markdown
<!-- WORK-JOURNAL:START 2026-07-10 -->
...日报内容...
<!-- WORK-JOURNAL:END 2026-07-10 -->
```

如果目标文件已存在，写入前会复制为同目录的 `.<日期>.work-journal.bak`；实际返回值会带回备份路径。支持三种冲突策略：

| 配置值 | 行为 |
| --- | --- |
| `append_under_marker`（默认） | 在同日期完整标记存在时原位替换该区块，避免重复；若没有完整标记，则在文件末尾追加一个新标记区块。 |
| `create_new` | 保留已有文件，寻找下一个可用文件名，例如 `YYYY-MM-DD-2.md`。 |
| `manual_copy` | 不显示自动导出按钮，界面提供复制预览 Markdown。 |

`preview_only` 是导出模式而非冲突策略；它只允许查看预览，不提供复制或写入动作。每次实际导出还会在本地 `obsidian_exports` 表记录日期、目标路径、内容哈希、导出时间和成功状态，便于追溯。
